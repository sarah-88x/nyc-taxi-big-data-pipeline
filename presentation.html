01. Problem Statement

Turning 101M Raw Taxi Logs into Actionable Decisions

Every yellow cab crossing NYC leaves a digital trace. But raw logs are noisy, massive, and scattered.

💥

The Raw Reality

9.36 GB of raw CSV files spanning 18 months, full of missing values, negative fares, and sensor recording glitches.

📉

Invisible Bottlenecks

Unidentified congestion spikes and route delays lead to lost revenue for fleet operators and poor passenger service.

🛠️

Unusable Unstructured Data

Raw CSVs are inefficient for querying. Without schema enforcement and Parquet columnar storage, queries choke.

🧠

Lack of AI Decision Tools

Traditional operators lack real-time streaming anomaly detection and predictive models for fare and duration estimation.

Stage 1

Dual Ingestion: 80% Batch + 20% Real Kafka Replay

To simulate a production environment, 80% of historical CSV files are stored directly in HDFS /raw/trips/. The remaining 20% is held back and replayed record-by-record via a Python producer into Kafka topic raw_taxi_trips.

  • ✓ Zero synthetic data generation — 100% real Kaggle taxi events.
  • ✓ Kafka Broker listening on kafka:29092 (internal) & localhost:9092 (host).
# kafka/producer.py
producer = KafkaProducer(
  bootstrap_servers=['localhost:9092'],
  value_serializer=lambda v: json.dumps(v).encode('utf-8')
)

for row in reader:
  producer.send('raw_taxi_trips', value=row)
  time.sleep(0.01) # Live replay speed
Stage 2

PySpark Quality Pipeline & Feature Engineering

PySpark loads raw CSVs, casts pickup/dropoff timestamps, derives trip_duration_seconds, and filters out invalid records (negative fares, passenger count = 0, distance > 100 miles, fare > $500).

  • ✓ Flags logical anomalies (e.g. positive duration with zero distance).
  • ✓ Persists cleaned Silver dataset to HDFS Parquet format.
# spark/batch/clean_taxi_data.py
df = df.filter(
  (col("fare_amount") >= 2.5) &
  (col("passenger_count") > 0) &
  (col("trip_distance") <= 100)
)

df.write.mode("overwrite").parquet(
  "hdfs://namenode:9000/processed/yellow_trips_clean.parquet"
)
Stage 3

Spark Structured Streaming & Instant Alerts

Spark Structured Streaming subscribes to raw_taxi_trips, processes events in micro-batches, and evaluates real-time alerting rules (e.g., fares > $150 or zero-distance high cost).

  • ✓ Outputs cleaned events to taxi_trip_events.
  • ✓ Outputs instant anomaly alerts to taxi_alerts.
# spark/stream/stream_processor.py
if fare_amount > 150.0:
  alert_reason = "High Fare Anomaly"
elif trip_distance == 0.0 and fare_amount > 30.0:
  alert_reason = "Zero Distance High Cost"

producer.send("taxi_alerts", value=alert_payload)
Stage 4

PostgreSQL Data Mart & Apache Superset BI

Aggregated OLAP models (hourly demand trends, zone pickup counts) are written to PostgreSQL via JDBC. Apache Superset connects directly to PostgreSQL to serve live executive dashboards.

  • ✓ daily_hourly_stats: Hourly trip counts & revenue.
  • ✓ zone_pickup_stats: Spatial borough activity summary.
# spark/batch/aggregate_trips.py
df_hourly.write.jdbc(
  url="jdbc:postgresql://postgres:5432/smart_taxi_db",
  table="daily_hourly_stats",
  mode="overwrite",
  properties=db_properties
)
Stage 5

Spark MLlib Predictive & Anomaly Models

Spark MLlib fits Random Forest Regressor models for predicting fare amounts and trip durations based on trip distance, pickup hour, day of week, and location IDs. Models are saved back to HDFS /models/.

  • ✓ Fare Model: Evaluates RMSE ($) & R² score.
  • ✓ Duration Model: Achieves ~4.42 min MAE on test set.
# spark/mllib/train_fare_model.py
rf = RandomForestRegressor(
  featuresCol="features",
  labelCol="fare_amount",
  numTrees=25, maxDepth=8
)

model.write().overwrite().save("hdfs://namenode:9000/models/fare_rf")

05. Production Engineering

Challenges & Production Resolutions

Real-world issues encountered and resolved during pipeline deployment.

Challenge 1

GitHub 100MB File Limit Isolation

Heavy raw CSV and Parquet files blocked repository commits.

✓ Configured strict .gitignore rules and decoupled raw storage to HDFS.
Challenge 2

PostgreSQL JDBC Driver Binding

Spark jobs threw ClassNotFoundException when attempting to export to PostgreSQL.

✓ Mounted postgresql-42.5.0.jar into cluster & passed via --jars.
Challenge 3

Kafka Dual-Listener Setup

Host python producer couldn't reach Kafka broker inside Docker network.

✓ Configured localhost:9092 for Host & kafka:29092 for Containers.
